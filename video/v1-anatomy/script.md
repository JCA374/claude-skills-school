# Anatomy of a skill

## A skill is a folder

A skill is a folder. Here is one of yours, the project site skill. The important file is the skill file, written in markdown. Next to it sit scripts that I can run, and templates that I copy into a new project.

## The header: name and description

The file starts with a short header. It has two fields. The name, and the description. The description says what the skill does, and, just as important, when to use it.

## The body: a briefing for a colleague

Below the header comes the body. It is plain language, written like a briefing for a new colleague. Steps to follow, conventions, and the rules you learned the hard way.

## Your nine skills, measured

Here are your nine skills, measured. Every skill file is short. Between fifty and ninety lines. The heavy work lives in the scripts, not in the instructions.

## Scripts do the heavy lifting

And this is the code behind them. About fourteen hundred lines in total. When I run a script, only its output comes back to me. So a big script costs me almost nothing to use.
