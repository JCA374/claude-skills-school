The ten habits of good skills

#HabitWhy
1Description = what + when + trigger wordsIt's the only part Claude sees before choosing. Claude tends to under-use skills, so be explicit.
2Short body, heavy scriptsInstructions cost context every time; a script's code costs nothing and runs the same every time.
3References for long or optional detail, with "read X when Y"Progressive disclosure: only the relevant checklist gets loaded.
4Explain the why, avoid shouting ALWAYS/NEVERA reason lets Claude handle cases the rule didn't foresee.
5Define done + a verification commandOtherwise "done" means "looks done". Your Pages check and voice.sh status are models for this.
6Point to a reference implementationA working example beats a page of explanation. Keep the path correct.
7Write lessons back into the skillThe chat is forgotten; the skill file isn't. Add a case, a rule and, if detectable, a test.
8Measure against a baselineskill-creator: with vs without, on 3–5 real prompts. Keep what wins.
9Mark ask-first actionsPublic repos, deletes, deploys: say in the skill that Claude asks first.
10No machine-specific surprisesPaths with the wrong case, hard-coded IPs, missing dependencies: the skill breaks silently on another day or machine.
