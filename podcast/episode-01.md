# Episode 01: What a skill is, and how I use one

Hi. This is the first episode of your skills school. You asked me to explain how skills work and how I work with them. So let's start at the very beginning.

A skill is a folder. Inside it there is one file that matters most. It is called the skill file. It starts with a short header with two fields: a name, and a description. Below the header come the instructions, written in plain language, the way you would brief a new colleague. Next to the skill file there can be scripts, reference documents and templates.

Now here is the part most people miss. When a session starts, I do not read your skills. I only see a list. Each line on that list is a skill's name and its description. That is about a hundred words per skill. So you can have dozens of skills installed and they cost almost nothing until they are needed.

When you ask me for something, I compare your request with those descriptions. If one fits, I load that skill. Only then do I read the full instructions. And only if the instructions point me to a script or a reference file do I open that too. A script is even cheaper. I run it, and only its output comes back to me. The code itself never has to fill my memory.

So there are three levels. The description is always there. The instructions arrive when the skill is chosen. The scripts and references arrive only when a step needs them. This is called progressive disclosure, and it is the whole trick.

That means the description is the most important sentence you will ever write in a skill. It is not a summary for humans. It is the trigger. If it does not say when to use the skill, I may never pick it. Your project site skill is a good example. Its description lists the words you actually say: a homepage, a progress page, replays, watch the model play, a film of the agent. That is why it fires when you need it.

You can also call a skill yourself. Type a slash and its name, and it loads straight away. Your deploy instructions for one of your web apps were meant to work like that. But there is a catch. They sit in a loose file in your skills folder, not in a folder of their own with a skill file inside. So right now they do not show up in my list at all. Moving them into a folder of their own, as a proper skill file, fixes it. The lessons on the website show how.

Let me tell you what you already have. You wrote a failure analysis report skill after the Tetris project. You have the project site skill and the podcast skill. And you have six skills that come from the audiobook studio. They are linked into your skills folder, so every project can use them. Speech flow and narration prep get the text ready. Kokoro narrate and listen check make the audio and check it. Audiobook assemble packages it. And voice text ties them all together. This very episode was made by those six skills.

On top of that come skills that Anthropic provides, like the skill creator, and the data and PDF plugins.

One more thing worth knowing. A skill is not the same as your personal instructions file. That file is read in every session, so it should hold short, permanent preferences. A skill holds a whole procedure, and it waits quietly until it is needed. Your instructions file already does this well. It says which skill to use for analysis and which for project sites, and then it leaves the details to the skills.

In the next episode, I will tell you how your skills learn. They have been getting better case by case, and the audiobook studio shows exactly how.
